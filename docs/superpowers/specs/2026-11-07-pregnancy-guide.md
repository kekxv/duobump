# DuoBump 双人孕期指南：首版需求基线

日期：2026-11-07。状态：用户已授权实施；可运行技术预览已完成，专业医学审核与公开部署待完成。

## 目标与用户

为中国大陆中文用户制作可部署到 GitHub Pages 的孕期静态指南，覆盖孕妇与伴侣共同参与的日常查询、孕周任务、饮食查询、待产准备与就医信息。以普通孕期科普为默认语境；高危妊娠、多胎、糖尿病、贫血等情况不输出自动治疗或营养处方。

## 首版范围

- 首页、三阶段总览与三个阶段详情、伴侣指南、妈妈护理、食物速查、三阶段菜单、待产清单、紧急就医、来源与免责声明。
- 孕周工具支持末次月经日期与医生确认预产期两种输入，以后者优先；可不填任何日期直接浏览。
- 约 60 条经过来源核查的食物记录、3 套一日菜单、约 30 项待产清单。数量是工作量预算，来源不完整的条目不为凑数发布。
- 食物关键词/别名搜索与分类筛选；全站中文搜索；待产清单本机持久化；孕周资料默认仅会话内使用，用户明确开启后才持久化。
- 移动端优先、键盘可用、可打印清单和就医页、站点内所有页面有直接就医入口。
- 不做登录、跨设备同步、短信推送、在线问诊、自动诊断、处方推荐、UGC、商品购买入口或完整离线 PWA。

## 内容与产品规则

1. 中国大陆产检流程优先参考国家卫生健康委、当地卫健部门及实际就诊医院；国际官方资料用于补充风险解释，冲突时明确适用地区并交由专业人员审核。
2. 孕期划分采用孕早期 <14+0、孕中期 14+0～27+6、孕晚期 ≥28+0；这是本产品展示口径，始终显示具体孕周，40 周后仍显示晚期并提醒按医嘱随访。
3. 不将 NT、血清学筛查、NIPT 混为诊断，不给出人人必须同时完成所有筛查的建议；产检计划标明常见窗口和个体化调整。
4. 食物分为“避免 / 限量或有条件 / 通常可选 / 证据不足”，使用文字与图形同时表达。区分食物本身与生熟、储存、杀菌及份量条件。
5. 不把山楂、桂圆、螃蟹等民间禁忌直接写成流产原因；不把核桃标为 DHA 来源；动物肝脏存在地区指南差异，不作为默认每周补铁食谱。
6. 不统一开具补铁、补钙剂量；饮食、补充剂和总摄入量分别解释。咖啡因按毫克总量说明，不以固定杯数换算。
7. 不把所有护肤水杨酸与维 A 酸同等禁用；区分外用低浓度、口服、高浓度换肤及处方制剂，疑问导向专业咨询。
8. 胎动提示围绕个人正常模式变化，不使用固定次数或“减少一半”作为唯一门槛；不让用户先计数一小时再求助。
9. 紧急页提供“立即呼叫 120 / 立即联系产科并就诊”行动分级；疑似破水立即联系产科、用卫生巾观察，不统一指导抬臀，也不让用户通过问卷排除急症。
10. 内容必须有来源机构、标题、URL、适用地区、资料核查日期和审核状态；未经过专业审核不能标注为“医生审核”。关键就医内容未经审核，不公开发布。

## 技术与验收

- 推荐 Astro + TypeScript + Tailwind CSS + Markdown/MDX/结构化 JSON + Pagefind。页面预渲染，仅工具按需加载客户端脚本。
- 使用 GitHub Actions 构建并部署 GitHub Pages；必须验证仓库子路径、直接打开详情页、搜索索引及静态资源路径。
- 日期只以用户设备当地日历日输入，转换为 UTC 日序号计算，避免时区和夏令时影响。
- 禁用 JavaScript 时仍能阅读六个模块、紧急页与免责声明；交互区域显示可理解的降级提示。
- 360/390/768/1280px 下无横向溢出，主要触控目标至少 44px；颜色不能作为唯一风险标识。
- 公开发布前通过类型检查、内容校验、核心逻辑单测、浏览器流程测试、子路径部署预览及内容审核。
- 性能目标：移动端 Lighthouse 性能 ≥90、无障碍 ≥95，记录设备与测试条件；作为验收目标，不预先宣称达成。
